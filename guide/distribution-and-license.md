## Distribution policy

**This repository contains no game data.** You must provide a disc image of your own copy of the game. The tools
extract, recompile and build everything locally from that image.

A ready-to-use installer ([installation.md](installation.md)) is published as a GitHub release (decision of the
project owner, 2026-10-19). The first release, 0.1.0, was published before the test on a clean Windows and before a
human installation test, which are still pending. The installer ships the recompiled executable and its libraries,
never any game data: players provide their own disc image. The fully decompiled C++ version (roadmap stage 2,
milestone D3) will later replace the recompiled executable in it. You can always build the game locally from your
own copy ([building.md](building.md)).

## Development

Most of the code and documentation is written with AI coding agents (Claude, by Anthropic, through Claude Code),
under the direction of the project owner. Every code change goes through the automated checks described in
[ROADMAP.md](../ROADMAP.md#how-changes-are-validated) ("How changes are validated"). Reviews: a separate AI review
agent before each merge, and the project owner's validation at the end of each stage. Commits written with AI carry a
`Co-Authored-By: Claude` line.

## Credits and third-party software

- [DolRecomp](https://github.com/ExpansionPak/DolRecomp) (GPL-3.0) — static recompiler from PowerPC to C. A small
  patch is kept in `tools/patches/dolrecomp/`. The single-precision helpers of `runtime/core/decomp/gc_float.h` are
  adapted from its CPU runtime (`src/cpu/cpu.c`, GPL-3.0-or-later), with attribution in the file.
- [Aurora](https://github.com/encounter/aurora) (MIT) — GameCube/Wii compatibility layer (GX, input) and its
  dependencies (Dawn, SDL3 and others, under their own licenses). Twelve small patches are kept in
  `tools/patches/aurora/` and applied by `tools/build.py`; what each one does: [technical.md](technical.md#aurora-patches).
- [Dear ImGui](https://github.com/ocornut/imgui) (MIT), through Aurora — the setup menu.
- [Dolphin](https://github.com/dolphin-emu/dolphin) (GPL-2.0-or-later) — reference for the original behavior;
  its AX audio voice processing is ported in `runtime/core/audio/`, with attribution in each file. The floating-point
  rounding of `runtime/core/decomp/gc_float.h` (Force25Bit, ForceSingle and NI_madd_msub of its interpreter,
  Copyright 2009 Dolphin Emulator Project) comes to this project through DolRecomp's helpers.
- [cbr_decomp](https://github.com/eavpsp/cbr_decomp) — function names in `games/chibi-robo/symbols/` come from its
  `decomp_dtk_main` folder (CC0 1.0). Thanks to its author for the groundwork.
- [doldecomp/melee](https://github.com/doldecomp/melee) — names of sysdolphin (HSD) functions in
  `games/chibi-robo/symbols/`. Names only, reused with its maintainers' permission
  ([doldecomp/melee#3681](https://github.com/doldecomp/melee/issues/3681#issuecomment-6375433261)); none of its code or
  comments is copied. Thanks to the Melee decompilation team.
- [xd-decomp](https://github.com/TeamOrre/xd-decomp) (CC0 1.0) — a second reference to check the sysdolphin
  matches. The 22 names that only xd-decomp gives are recorded as hypotheses in
  `games/chibi-robo/symbols/supplement.tsv`; none of them is in the symbol maps.
- [unplug](https://github.com/adierking/unplug) (MIT) — the stage numbers in `games/chibi-robo/game.toml`
  (`[stage.names]`), and the reference for the disc and stage formats.
- [Ghidra](https://github.com/NationalSecurityAgency/ghidra) (Apache-2.0) — binary analysis.
- [REA](https://github.com/morluto/rea) (MIT) — optional reverse-engineering assistant over Ghidra
  (`tools/rea.py`, see [technical.md](technical.md#optional-reverse-engineering-with-rea)); not shipped, installed in

- [LLVM/clang](https://github.com/llvm/llvm-project) (Apache-2.0 with LLVM exception),
  [Ninja](https://github.com/ninja-build/ninja) (Apache-2.0).
